Материалы пересабмита по `CIRPJ-D-26-00824` (CIRP J. Manuf. Sci. Technol.,
отклонена 2026-08-23). Каталог самодостаточен: код здесь не зависит от `.pkl`
и запускается без GPU.

## Быстрый старт

```bash
python publication/tests/test_pipeline.py          # ничего не требует, кроме numpy/scipy
```

Опознать содержимое любого `.pkl` (какая величина в какой плоскости):

```bash
python publication/code/verify_pkl.py --pkl y_stress.pkl --xpkl X_stress.pkl \
    --raw <распакованный Raw_Data>
```

Пересобрать корректный датасет и прогнать матрицу:

```bash
python publication/audit/run_raw_audit.py --root <Raw_Data> --out audit.npz
python publication/code/dataset.py --allcols allcols.npz --profr audit.npz --out stress.npz
python publication/experiments/run_matrix.py --dataset stress.npz --out runs.csv --stage main
python publication/experiments/make_results.py --csv runs.csv --out publication/RESULTS.md
```

Воспроизвести аудит данных (нужен релиз `raw-data-v1`, 1.2 ГБ):

```bash
python publication/audit/run_raw_audit.py --root <распакованный Raw_Data> --out audit.npz
python publication/audit/make_report.py   --npz audit.npz
```

## Что здесь важно знать сразу

**Главное.** В `y_stress.pkl`, на котором обучались все шесть моделей статьи,
лежат не те величины: по плоскостям это `(S.Max. Prin, S.Mid. Prin,
S.Min. Prin, σ_rr)` — три главных напряжения и радиальная компонента. τ_rz,
σ_θθ и σ_zz в обучающих данных отсутствуют вовсе (E-18). Поэтому физический
лосс не был уравнением равновесия, а покомпонентные результаты статьи имеют
неверные подписи. Граничное условие при этом оказалось верным случайно — и
поэтому дефект дожил до подачи в журнал.

Ещё четыре вещи, подтверждённые измерением, а не рассуждением:

1. окно «25–75 %» — **осевое**; радиальный профиль покрывает весь радиус,
   свободная поверхность при `r_norm = 1`, а не 1.5 (E-01);
2. редукция уравнений равновесия оправдана для радиального уравнения
   (отброшено 1.3 %) и **не** оправдана для осевого (68 %) — E-02;
3. «три бэкенда автодифференцирования» — на деле два: DeepXDE в репозитории
   работает на PyTorch, а производные torch и JAX на одних весах совпадают до
   8.7e-15 (E-19);
4. 13.2 % наборов сырой сетки — один и тот же расчёт под несколькими метками
   трения (E-06).

**Что сделано в ответ.** Датасет пересобран из сырых `.rpt`; написан единый
тренер, где семейства моделей отличаются только составом функции потерь;
прогнана экспериментальная матрица — экстраполяционные сплиты × сиды, кривые
обучения, устойчивость к порче меток, torch против JAX, ablation «z во входе /
полная форма равновесия». Результаты — `RESULTS.md`.

Подробности и что с этим делать — в `PLAYBOOK.md`.
