# Повторная выгрузка из `.odb` — что и как

Единственный шаг, качественно меняющий картину с валидацией: на имеющихся 1756
наборах усилие волочения не извлекается (сечение разгружено), а на 158
«незавершённых» — извлекается, но они не входят в датасет. Выгрузка `RF`
хотя бы для 30 режимов **из самого датасета** снимает это противоречие.

## Шаг 1 — за минуту: живы ли файлы

На машине, где смонтированы диски `E:`, `H:`, `V:`:

```
python check_odb_alive.py reexport_list.csv
```

Обычный Python, Abaqus не нужен. Печатает по партиям, сколько `.odb` на месте.
Отобранные 30 режимов лежат в шести партиях:

| партия | `.odb` |
|---|---|
| `H:/Calculations_Abaqus_2022/Vel_250` | 7 |
| `E:/Abaqus_calc/Vel_40/odb/Correct` | 7 |
| `E:/Abaqus_calc/Vel_20/odb/Correct` | 6 |
| `V:/Wire_drawing/2026/odb` | 5 |
| `E:/AISI_1020/Vel_5_updated` | 4 |
| `V:/Wire_drawing/2026/odb/Vel_10_updated` | 1 |

Для проверки всех 2443: `python check_odb_alive.py all_odb_paths.csv`.

## Шаг 2 — выгрузка

```
abaqus python reexport_fields.py reexport_list.csv out_dir
```

Сначала на 2–3 файлах, посмотреть `out_dir/missing.txt`, затем на всех.

Что выгружается и зачем:

| поле | зачем |
|---|---|
| `RF` на опорной точке волоки, **по всем кадрам** | усилие волочения — прямое сравнение с Зибелем и Авитцуром на данных статьи |
| `PEEQ` | фактор избыточной работы количественно; сейчас только нижняя оценка по `LE` |
| `CPRESS`, `CSHEAR` | член трения через контактные напряжения |
| `S`, `LE`, `COORD` | сверка с прежней выгрузкой |
| `TEMP`/`NT11` | ожидается, что нет — подтверждение, что расчёт не термомеханический |

Кадры: последний плюс четыре равномерно по шагу. Промежуточные кадры — это
то, чего не хватало: они показывают напряжение волочения, пока проволока в
волоке.

## Как отобраны 30 режимов

Стратифицированно по датасету v2: все 6 уровней Q, все 6 уровней k, все 5
скоростей, все 3 уровня μ, полууглы 4 / 8 / 20°. Предпочтение крайним по α —
там аналитика чувствительнее.

## Что делать с результатом

Положить `out_dir` рядом и прислать. Дальше — `publication/code/analytical.py`
считает Зибеля и Авитцура для каждого режима и сравнивает с `RF/(πR_f²)`.
