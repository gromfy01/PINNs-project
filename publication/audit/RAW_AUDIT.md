# Аудит сырых данных Abaqus

Сгенерировано `publication/audit/make_report.py` по релизу `raw-data-v1`.
Все утверждения ниже получены из `.rpt`, а не из рукописи, `docs/` или
предыдущего handover — там, где источники расходятся, прав `.rpt`.

Файлов обработано: **2443** (ошибок парсинга 0).

## 1. Раскладка колонок `.rpt`

Подтверждена по заголовку Field Output Report:

```
0 Node Label   1 COORD.COOR1 (r)   2 COORD.COOR2 (z)
3..6   LE.LE11 LE.LE22 LE.LE33 LE.LE12   (ε_rr, ε_zz, ε_θθ, γ_rz)
7..10  S.Mises  S.Max/Mid/Min Prin
11..14 S.S11 S.S22 S.S33 S.S12          (σ_rr, σ_zz, σ_θθ, τ_rz)
```
Соглашение осесимметричных элементов Abaqus: 1 = r, 2 = z, 3 = θ.
`preprocessing/rpt_utils.py` читает эти колонки правильно.

## 2. Что означает окно «25–75 %»  (E-01)

| величина | медиана | мин | макс |
|---|---|---|---|
| доля осевого размаха, попавшая в окно | 0.4985 | 0.1600 | 0.5000 |
| r_min(окно) / R | -0.0001 | -0.0084 | 0.0000 |
| r_max(окно) / R | 0.9958 | 0.7157 | 1.0000 |

**Вывод.** Окно 25–75 % — **осевое** (по `z`, зона выхода на стационар).
Двадцать радиальных точек покрывают **весь** радиус: `r_norm = 0` — ось,
`r_norm = 1` — свободная поверхность. Формула `r_phys = R·(0.25 + 0.5·r_norm)`
из прежнего handover и константа `R_EXTRAP_FREE_SURFACE = 1.5` в
`models/*.py` данным противоречат: `r_norm = 1.5` — это `1.5 R`, точка вне
материала.

## 3. Порядок компонент  (E-04)

Стек, который строит `preprocessing_res_np`, — `(s_rr, s_tt, s_zz, s_rz)`.
Средний модуль по всем наборам:

| слот стека | на оси, МПа | на внешней точке, МПа |
|---|---|---|
| 0 — s_rr | 91.30 | 3.77 |
| 1 — s_tt | 91.33 | 114.44 |
| 2 — s_zz | 231.51 | 129.09 |
| 3 — s_rz | 0.24 | 0.48 |

Traction-free (`σ_rr ≈ 0`, `τ_rz ≈ 0`) выполняется в слотах 0 и 3, то есть
стек **уже физический**. Значит `PLANE_ORDER = [2, 0, 1, 3]` поверх него даёт
`(σ_zz, σ_rr, σ_θθ, τ_rz)` — перепутанные компоненты. Либо `.pkl` собран
не тем скриптом, что лежит в репозитории, либо константа неверна; в любом
случае опубликованный репозиторий сейчас не воспроизводит датасет.

Куда именно разъехалось. `docs/data_format.md` приводит проверку ГУ после
применения `PLANE_ORDER`: `σ_rr ≈ 5.9`, `σ_θθ ≈ 144`, `σ_zz ≈ 99`, `τ_rz ≈ 3.8` МПа.
Обратной подстановкой `out = (P2, P0, P1, P3)` получаем, что в `.pkl` плоскости
лежат в порядке **(σ_θθ, σ_zz, σ_rr, τ_rz)**, тогда как коммитнутый
`preprocessing_res_np` укладывает **(σ_rr, σ_θθ, σ_zz, τ_rz)**. Чинить одним из
двух способов, но обязательно с записью в статье: либо пересобрать `.pkl`
текущим препроцессингом и поставить `PLANE_ORDER = [0, 1, 2, 3]`, либо привести
порядок стека в `preprocessing_res_np` к тому, каким собран `.pkl`.
Однострочная проверка на настоящем `.pkl`: та плоскость, у которой
`mean|y[p][:, -1]|` минимален, и есть `σ_rr`.

## 5. Дубликаты по μ  (E-06)

Наборов, у которых при совпавших `(Q, k, α, v)` профиль **побитово** равен
профилю другого набора, отличающегося только меткой μ: **323** из 2443
(**13.2 %**).

Комбинаций `(Q, k, α, v)`, где все имеющиеся уровни μ дали один и тот же
результат: **159**.

Проверено сильнее: у 40 случайно выбранных пар совпали **все числовые
данные `.rpt` целиком** (40 из 40), при этом md5 файлов различаются —
расходятся только заголовки (путь к `.odb`, отметка времени). То есть это
не «трение не повлияло», а **один и тот же расчёт, размноженный под тремя
метками трения**. Использовать μ как ось экстраполяции нельзя, а таблицу
факторов в статье надо сопроводить этой оговоркой.

Цифра «~31 % μ-дублей» из `docs/data_format.md` не воспроизводится
ни на каком порядке фильтров; на сырой сетке это 13.2 %.

## 6. Отброшенные осевые члены равновесия  (E-02)

Поля внутри осевого окна биннингованы на сетку 20 × 20 (медиана в ячейке),
производные — `numpy.gradient` по физическим координатам. По каждому набору
берётся медиана модуля члена, ниже — перцентили этих медиан по 2443 наборам.

| член | 25 % | медиана | 75 % |
|---|---|---|---|
| ∂σ_rr/∂r | 2.32e+03 | 5.81e+03 | 9.58e+03 |
| (σ_rr − σ_θθ)/r | 2.27e+03 | 5.43e+03 | 9.62e+03 |
| ∂τ_rz/∂z *(отброшен)* | 64.3 | 107 | 193 |
| ∂τ_rz/∂r | 239 | 326 | 543 |
| τ_rz/r | 73.3 | 110 | 190 |
| ∂σ_zz/∂z *(отброшен)* | 214 | 320 | 505 |

Отношение отброшенного к сумме удержанных, МПа/м на МПа/м:

| уравнение | 25 % | медиана | 75 % | доля наборов с отношением > 0.2 |
|---|---|---|---|---|
| радиальное: `∂τ_rz/∂z` / (`∂σ_rr/∂r` + `(σ_rr−σ_θθ)/r`) | 0.004 | 0.013 | 0.039 | 4.7 % |
| осевое: `∂σ_zz/∂z` / (`∂τ_rz/∂r` + `τ_rz/r`) | 0.565 | 0.678 | 0.863 | 100.0 % |

Насколько меняется сама невязка при переходе к редуцированной форме
(медиана относительного отклонения):

* радиальное уравнение — **0.061**;
* осевое уравнение — **0.323**.

**Вывод.** Для радиального уравнения отбрасывание `∂τ_rz/∂z` оправдано
численно и это можно написать в статье. Для осевого — **не оправдано**:
отброшенный член того же порядка, что удержанные. Выражение
`∂τ_rz/∂r + τ_rz/r`, которое считает код, осевым равновесием не является.

## 7. Нарушение traction-free самими данными FEM

В крайней радиальной точке профиля (`r_norm = 1`): средний `|σ_rr|` =
**3.77 МПа**, `|τ_rz|` = **0.48 МПа**.

Это базовая линия для Fig. 11–12: точное условие `σ_rr = τ_rz = 0` —
физический приор, которому сам источник данных удовлетворяет лишь с этой
точностью. Метрику нарушения ГУ у моделей осмысленно печатать только
рядом с этой строкой.
