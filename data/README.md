# data/

Каталог для данных конечно-элементного моделирования. В git не коммитится.

## Что должно лежать после распаковки

```
data/processed/
├── X_stress.pkl   # (4, 2028, 5)  — параметры процесса по плоскостям Abaqus
├── y_stress.pkl   # (4, 2028, 20) — компоненты тензора остаточных напряжений
├── X_strain.pkl   # (4, 2437, 5)
└── y_strain.pkl   # (4, 2437, 20) — компоненты полного тензора деформаций
                                     (для уравнений совместности Сен-Венана)
```

Полное декартово произведение факторной сетки — `7 × 6 × 5 × 3 × 5 = 3150`
комбинаций (μ имеет **три** уровня; четвёртый, `0.002`, — опечатка в имени
одного задания, см. `docs/data_format.md`). После отбраковки несошедшихся и
нефизичных расчётов остаётся **2028 наборов для напряжений** и **2437 наборов
для деформаций** (разница — дополнительный фильтр по физичности σ_eff,
применённый только к стресс-набору). Сырой релиз `raw-data-v1` содержит 2443
файла `.rpt`.

`20` — число радиальных точек. Они покрывают **весь** радиус (`r_norm = 0` —
ось, `r_norm = 1` — свободная поверхность); порог «25–75 %» относится к
**осевой** координате и задаёт окно, в котором процесс вышел на стационар.
Подробности и проверка по сырым данным — `publication/audit/RAW_AUDIT.md`.

## Семантика осей

`X[plane, set, feature]` — одинакова для всех 4 плоскостей Abaqus, поэтому в коде используется `X[0]` как канонический. Порядок features: `Q, k, α, μ, v`.

`y[plane, set, point]` — индекс плоскости отличается от физических компонент. Преобразование к физическому порядку:

| Тип    | Перестановка               | Физические компоненты              |
|--------|----------------------------|------------------------------------|
| stress | `PLANE_ORDER = [2,0,1,3]`  | `(σ_rr, σ_θθ, σ_zz, τ_rz)`         |
| strain | `PLANE_ORDER = [2,0,1,3]`  | `(ε_rr, ε_θθ, ε_zz, ε_rz)`         |

Обучающие pkl деформаций (`y_strain.pkl`) хранятся в той же плановой
раскладке, что и `y_stress.pkl`, поэтому одна и та же перестановка
`[2, 0, 1, 3]` применяется к обоим массивам — это и реализовано в
`models/strain/*.py` и `launch/strain/*.ipynb`. Сдвиговая компонента
записана в тензорной форме `ε_rz` (связь с инженерным сдвигом —
`γ_rz = 2·ε_rz`).

Эти константы **обязательно** применяются и к прогнозу модели, и к
эталону FEM на всех графиках сравнения — иначе R² нормальных компонент
уходит в отрицательную зону.

> Замечание про §5.2.2 ВКР. В тексте ВКР для деформаций указана
> перестановка `PLANE_ORDER_STRAIN = [1, 0, 2, 3]` — она относится к
> внешнему тест-набору деформаций (`TEST_PLANE_ORDER` в
> `launch/strain/*.ipynb`), а не к основному `y_strain.pkl`.

## Известные дефекты факторной сетки

Перед любым обучением применять `publication/code/filters.py::filter_dataset`:

| дефект | масштаб (сырая сетка 2443) |
|---|---|
| `μ = 0.002` — опечатка `fric_02` в имени задания | 1 набор |
| `Q = 0.25` — упругая разгрузка, вырожденный выход | 275 наборов |
| дубликаты по μ (один расчёт под несколькими метками трения) | 323 набора, 13.2 % |
| ручной список FEM-артефактов из `launch/stress/*.ipynb` | 7 наборов |

Скорость `v = 5` м/мин представлена 122 наборами против 554–607 у остальных
уровней — сетка несбалансирована по этой оси.

## Откуда взять данные

Данные распространяются по запросу к научному руководителю проекта.

После получения архива положить `.pkl` файлы в `data/processed/` и запустить любой ноутбук из `notebooks/`.

## Извлечение из .odb (для справки)

Сами `.odb` файлы Abaqus и скрипт извлечения через Abaqus Python API в репозитории не находятся — пайплайн обработки запускается на инженерной машине с установленным Abaqus, а здесь работа ведётся уже с готовыми `.npy` / `.pkl` массивами.
