# Формат данных

## Источник

Данные получены из конечно-элементного моделирования процесса осесимметричного волочения проволоки в Abaqus. Извлечение из `.odb` выполнено отдельным скриптом через Abaqus Python API.

## Параметры процесса

Каждый набор задаётся пятью скалярными параметрами (табл. 5.2 ВКР):

| Символ | Имя                       | Диапазон                                | Единицы | Уровней |
|--------|---------------------------|-----------------------------------------|---------|---------|
| Q      | степень обжатия           | 0.015, 0.025, 0.05, 0.10, 0.15, 0.20, 0.25 | %       | 7       |
| k      | коэф. калибрующего участка | 0.0, 0.1, 0.3, 0.5, 0.75, 1.0           | —       | 6       |
| α      | полуугол волоки           | 4, 8, 12, 16, 20                        | градусы | 5       |
| μ      | коэф. трения Кулона       | 0.025, 0.05, 0.10                       | —       | 3       |
| v      | скорость волочения        | 5, 10, 20, 40, 250                      | м/мин   | 5       |

Полное декартово произведение `7 × 6 × 5 × 3 × 5 = 3150` комбинаций.
После отбраковки несошедшихся и нефизичных расчётов остаётся **2028 наборов
для напряжений** и **2437 наборов для деформаций** (разница — дополнительный
фильтр по физичности σ_eff, применённый только к стресс-набору).

## Радиальная сетка

В каждом наборе значения тензора напряжений (или пластической деформации) экспортированы в 20 равномерных радиальных точках на промежутке 25–75 % высоты сечения. Этот диапазон выбран намеренно — за пределами зоны выхода процесса волочения на стационар. Численно радиус нормирован: `r ∈ [0, 1]`.

## Формы массивов

```
X_stress[plane, set, feature]  shape = (4, N_sets, 5)
y_stress[plane, set, point]    shape = (4, N_sets, 20)
```

Первая ось `plane` — это четыре плоскости извлечения данных Abaqus. Все четыре плоскости содержат одинаковые значения параметров `(Q, k, α, μ, v)`, так что `X[0]` достаточно для всех целей.

## Перестановка PLANE_ORDER

Индексы плоскостей Abaqus **не совпадают** с физическими компонентами тензора. Для приведения к физическому порядку нужна перестановка:

```python
PLANE_ORDER_STRESS = [2, 0, 1, 3]   # (σ_rr, σ_θθ, σ_zz, τ_rz)
PLANE_ORDER_STRAIN = [1, 0, 2, 3]   # (ε_rr, ε_θθ, ε_zz, γ_rz)
```

Соответствие подтверждено через проверку граничного условия отсутствия
поверхностных усилий: после применения PLANE_ORDER компонента σ_rr на
поверхности `r = r_max` действительно близка к нулю (усреднённый модуль
σ_rr ≈ 5.9 МПа, τ_rz ≈ 3.8 МПа против σ_θθ ≈ 144 МПа, σ_zz ≈ 99 МПа).
Для strain-набора та же перестановка `[2, 0, 1, 3]` проверена по условию
несжимаемости: |ε_rr + ε_θθ + ε_zz| ≈ 10⁻³ по полному датасету.

**Замечание про текст ВКР.** В §5.2.2 ВКР для деформаций декларирована
перестановка `PLANE_ORDER_STRAIN = [1, 0, 2, 3]` — это касается отдельного
внешнего тест-набора деформаций (`TEST_PLANE_ORDER` в launch-ноутбуках
`launch/strain/*.ipynb`). Основные обучающие pkl `data/processed/y_strain.pkl`
хранятся в том же плановом порядке, что и `y_stress.pkl`, и обрабатываются
константой `PLANE_ORDER = [2, 0, 1, 3]` — это видно по коду модулей
`models/strain/*.py`.

**Ключевая ловушка:** при сравнении прогноза модели с эталоном FEM
перестановку нужно применять **к обоим массивам**. Если применить только
к прогнозу, R² нормальных компонент уходит в большую отрицательную
область — кажется, что модель сломана, хотя сломан только график.

## Стандартизация

Перед обучением:

- Входы (`Q`, `k`, `α`, `μ`, `v`, `r`) — z-score нормировка, статистики считаются только по train + val части (без holdout).
- Выходы (`σ_rr`, `σ_θθ`, `σ_zz`, `τ_rz`) — тоже z-score нормировка по 4 компонентам.

Параметры нормировки сохраняются в бандле как `mean_X`, `std_X`, `scaler_y_mean`, `scaler_y_std` — они нужны для инференса.

Исключение для VPINN (strain): радиальная координата `r` **не** z-нормируется. В бандле это выражено как `mean_X[5] = 0`, `std_X[5] = 1`. Это сделано из-за того, что VPINN применяет к `r` Fourier embedding, который ожидает входной диапазон `[0, 1]`.

## Holdout split

Для **напряжений** (2028 расчётов):

```python
seed = 42
holdout_frac = 0.15
n_holdout   = round(2028 * 0.15) = 304
n_trainval  = 1724
```

Для **деформаций** (2437 расчётов) единая holdout-выборка не выделяется —
все наборы используются в 5-fold group-aware кросс-валидации.

Разбиение **group-aware** — все 20 радиальных точек одного набора параметров остаются в одной части. Реализовано через `numpy.random.default_rng(42).choice` на уровне индексов наборов, затем индексы наборов разворачиваются в индексы строк.

Все шесть stress-бандлов используют одинаковые `holdout_set_indices` и `trainval_set_indices` — это явное условие сопоставимости результатов.

## Известные проблемы качества

Эти артефакты выявлены при аудите holdout-выборки и должны фильтроваться/диагностироваться:

1. **~8 наборов с Q = 0.250** — попадают в режим упругой разгрузки, выходы близки к нулю по всем компонентам. Малая дисперсия делает R² патологически чувствительным: при RMSE ≈ 5 МПа метрика R² уходит в `-∞`.
2. **~31 % наборов с μ-инвариантностью** — для этих `(Q, k, α)` все четыре значения μ дают побитово одинаковые выходы. Модель тратит ёмкость на изучение несуществующей зависимости от трения.
3. **Изолированные FEM-артефакты** — например, набор #439: `σ_θθ ≈ +255 МПа` константа при `std = 6.7` МПа, тогда как все другие наборы в той же `(Q, k, α)` группе имеют `σ_θθ_mean ∈ [+1.6, +7.9]` МПа. Диагноз: одиночный сбой сходимости Abaqus, не системный.

Классификатор в `evaluation/outlier_diagnosis.py` помечает наборы как `normal` / `low_signal` / `fem_artifact` по порогам:

```
LOW_SIGNAL_STD       = 10 МПа     # std по всем 4×20 значений набора
ARTIFACT_MEAN        = 100 МПа    # |mean| хотя бы одной компоненты
ARTIFACT_STD         = 15 МПа     # абсолютный std
ARTIFACT_RELATIVE_STD = 0.10      # std / |mean|
```
