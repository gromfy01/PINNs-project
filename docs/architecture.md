# Архитектура моделей и обоснование решений

## Общая постановка

Для каждой пары (стресс, деформация) обучается шесть моделей разной природы, чтобы сравнить чисто-данные подход с физически-информированным:

| Архитектура   | Природа                          | Backend          |
|---------------|----------------------------------|------------------|
| MLP-baseline  | data-driven                      | PyTorch          |
| MLP-grid      | data-driven, гипер-grid          | PyTorch          |
| PINN-PyTorch  | физика через autograd            | PyTorch          |
| PINN-DeepXDE  | физика через DeepXDE             | DeepXDE/PyTorch  |
| PINN-JAX      | физика через JAX/Optax           | JAX/Flax         |
| VPINN         | физика в слабой форме            | PyTorch          |

Выбор PyTorch как основного backend'а связан с тем, что у DeepXDE есть PyTorch-режим (`DDE_BACKEND=pytorch`), что позволяет переиспользовать инфраструктуру обучения и сохранения весов между PINN-DeepXDE и PINN-PyTorch. JAX-трек самостоятельный.

## Вход модели

```
x = (Q, k, α, μ, v, r)   shape: (batch, 6)
```

Все модели принимают шесть скаляров на вход. Z-нормировка применяется к первым пяти; для VPINN-strain `r` остаётся ненормированным (см. data_format.md).

## Выход модели

```
y = (σ_rr, σ_θθ, σ_zz, τ_rz)   shape: (batch, 4)
```

После прохождения сети применяется обратная z-нормировка через `scaler_y_mean`, `scaler_y_std`, чтобы вернуть значения в физические единицы (МПа для напряжений).

Дополнительно для VPINN после линейного слоя стоит `OutputScaler` — обучаемый сдвиг и масштаб на каждую компоненту. Это нужно, потому что в слабой форме интегральное представление потерь имеет другой масштаб, и стандартного z-score нормирования не хватает.

## Fourier feature embedding

Радиальная координата `r` пропускается через фиксированное Fourier-кодирование:

```python
γ(r) = [sin(r · B · 2π), cos(r · B · 2π)],   B ~ N(0, σ²)   # фиксировано
```

Это противодействует **спектральному смещению** MLP — они хуже учат высокочастотные функции от низкоразмерного входа. Профили напряжений по `r` имеют в среднем 1–2 узла, и MLP без Fourier-кодирования сглаживает их в линейные тренды.

В VPINN число частот `n_freq = 8` — это даёт `2 × 8 = 16` дополнительных признаков. Stress PINN использует `n_freq = 16`.

## Группо-ориентированное разбиение

Все 20 радиальных точек одного набора параметров попадают в одну часть `(train | val | test)`. Случайное построчное разбиение даёт утечку данных через сильную внутрисетную корреляцию: соседние `r`-точки имеют почти линейную взаимосвязь, и любая модель тривиально интерполирует пропущенную точку из соседей.

## Физические потери в нормированных координатах

Уравнения равновесия и совместности всегда вычисляются в **нормированной** системе координат, не в физической (МПа, мм). Если записать `∂σ/∂r` в МПа/мм, типичная величина градиента ~`10⁵`, тогда как градиенты от data-loss ~`10⁰`. Это приводит к коллапсу обучения: оптимизатор ловит ноль физической потери, игнорируя данные.

Решение — записать всё в `(r̄, σ̄)` где `σ̄ = (σ − μ_y) / σ_y`, `r̄ = r/r_max`. Тогда величины гладких членов сравнимы.

## Двухфазное обучение для DeepXDE

Adam → L-BFGS. Первая фаза находит грубый минимум, вторая дотачивает по второму порядку. L-BFGS не используется в PyTorch-PINN и MLP — там Adam с косинусным расписанием LR сходится так же или лучше, а L-BFGS требует full-batch, что плохо масштабируется.

## Ключевой результат для деформаций

Для пластических деформаций чистый MLP уверенно бьёт PINN (`R² ≈ 0.97` против `0.85`). Причина — структура данных: ~95 % дисперсии находится **между** наборами параметров, а не вдоль радиальной координаты. Профили `ε^p(r)` для одного набора почти горизонтальны.

Физическая потеря в этом режиме штрафует радиальную форму профиля, которая и так почти константа — потеря около нуля по построению, и обучение фактически идёт только на `L_data`. При этом физический член добавляет шум в градиенты, замедляя сходимость.

Это **не** означает, что физическая постановка ошибочна. Это означает, что текущий датасет (одна z-плоскость, только пластика) не информативен с точки зрения уравнений совместности Сен-Венана. После получения 2D total strain экспорта картина может развернуться.

## Ключевой результат для напряжений

PINN-DeepXDE имеет лучший RMSE на holdout (12.42 МПа против 13.08 МПа у MLP-grid). По τ_rz и SMAPE по большинству компонент лидирует MLP-grid. По R² трёх нормальных компонент лидирует PINN-DeepXDE.

Главный физический вывод: на нормальных наборах нарушение ГУ у MLP-моделей сравнимо с FEM-источником (~4–5 МПа), а у PINN — в 4–6 раз ниже (~0.6–0.9 МПа). Это означает, что **только** BC-loss даёт строгий физический prior, не зависящий от качества данных. Data-loss, наоборот, по построению ограничен качеством FEM и даже на специальных наборах с FEM-артефактами начинает воспроизводить артефакт (~20–35 МПа BC violation у MLP против 1–3 МПа у PINN).

## Универсальный numpy-loader

Файл `models/loader.py` умеет загружать веса из любого из трёх backend'ов (`torch_state_dict`, `flax_params_numpy`, `state_dict_np`) и делать forward pass через чистый `np.matmul`. Это нужно для двух сценариев:

1. **Воспроизведение результатов без установки PINN-фреймворков** — если кому-то достаточно посмотреть прогноз, можно обойтись только numpy.
2. **Inference на холодном железе** — сервер без GPU, без CUDA-сборки PyTorch.

Конвенция размещения весов:
- DeepXDE → ключи `linears.{i}.weight`, `linears.{i}.bias`, без активации между линейными слоями (она хранится отдельно).
- PyTorch nn.Sequential → ключи `net.{2i}.weight`, `net.{2i}.bias` (нечётные индексы — модули активаций).
- Flax — вложенный dict `{'Dense_{i}': {'kernel', 'bias'}}`. Kernel в Flax хранится как `(in, out)`, в PyTorch как `(out, in)` — нужно транспонировать.
- VPINN-strain дополнительно содержит ключи `r_embed.B` (Fourier частоты) и `scaler_out.scale/shift` — loader детектирует это автоматически.
